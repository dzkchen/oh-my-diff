# External client example

An independent-author API `0.2.0-experimental.5` mod that owns its own client adapter: a text renderer process that joins the session over the client protocol (`omd-client/1`) with the SDK in `@oh-my-diff/mod-api/client`.

- The `terminal` handler lists the attach roster from `input.clients` in the `external_clients` list. Space/Enter on a row, or `omd/action` from an attached client, runs `external_client:pick` with the row's client id. A status line, an 8×1 `raster` drawn once by a timer with `terminal.blit`, and an SVG `image` written with `evidence.write` on `start` complete the view. The terminal shows the image's alt text; renderers that list `svg` draw it.
- A pointer press on the badge records `component_event.client`, so the status line names the client that clicked it (`terminal` for the local TUI).
- The `launch` command hops through `events.publish` to the mod's own `channel` handler, because slash commands cannot start processes. The handler resolves `node` with `process.which` and starts `node <client_path>` with `process.start {sandbox: 'none'}` under the `os` grant (`os_access.programs: ['node']`, network on for `ws://` listeners). The listen URL and the capability-token file path reach the process as `EXTERNAL_CLIENT_URL` and `EXTERNAL_CLIENT_AUTH_FILE` (both listed in `exec_environment`), so the token itself never passes through the mod.
- `client.mjs` connects with `kind: 'text'` and prints to stderr, because a process the mod starts uses stdout as its framed message channel. It prints every `omd/view/updated` snapshot as text, drawing components it cannot show (images, rasters, inputs) as the SDK's `unsupported()` error with their fallback text, the roster and mirrored notices, then sends one action on its own roster row once a view lists it and prints the result. The SDK re-attaches after a disconnect.

Run a host with a listener, for example `codex --listen ws://127.0.0.1:4500 --ws-auth capability-token --ws-token-file /abs/token` (TUI co-attach) or `codex app-server --listen unix:///abs/omd.sock` (headless). Set the mod's `listen_url`, `token_file` (empty for `unix://`) and `client_path` (the absolute path of this `client.mjs` inside a project that depends on `@oh-my-diff/mod-api`), grant `terminal`, `commands`, `lifecycle`, `events`, `store`, `exec` and `os`, then run its `launch` command. You can also run `EXTERNAL_CLIENT_URL=unix:///abs/omd.sock node client.mjs` directly.

`mod.test.json` runs offline: start writes the badge, the launch command publishes the hop, the channel handler starts the process, a pick and a client's pointer press update state, and the mounted view lists one attached text client. Run it with `python3 scripts/mod_host_check.py --omd-mod <omd-mod> --no-commands --scenarios external_client`.
