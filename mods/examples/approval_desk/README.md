# Approval desk example

An independent-author API `0.2.0-experimental.5` mod and client adapter that share approval history between the terminal and attached external clients over the client protocol (`omd-client/1`). It is unrelated to `external_client` and composes beside it.

- The `approval` middleware records every approval request (command, files or host) and returns null, so the native decision is unchanged; `approval_result` records the decision and its source and shows a toast with `terminal.notice`.
- The `terminal` handler wraps the sidebar (`mode: 'wrap'` with a `slot`), so another mod's sidebar stays below the desk: a `multiselect` of approval kinds (`Alt+k` focuses it, Space toggles, Enter applies), a controlled `input` note, a `list` of requests with their decisions (Enter inspects one), a line with an OSC 8 link and the inspected request's details.
- `client.mjs` connects with a GUI-shaped renderer (`svg`, `png`, `cells`, pixel pointer), resumes every loaded thread and each new one, answers `item/commandExecution/requestApproval` and `item/fileChange/requestApproval` with `APPROVAL_DESK_DECISION` (`decline` by default), reports `serverRequest/resolved` when another client or the terminal answered first, and prints one JSON line per view, approval and unsupported component to stdout. Run it yourself with `APPROVAL_DESK_URL=unix:///abs/omd.sock node client.mjs` against `codex app-server --listen unix:///abs/omd.sock` or `codex --listen unix:///abs/omd.sock`.

Grant `terminal`, `commands`, `approvals`, `middleware` and `store`. `mod.test.json` runs offline: two approval requests, one decision, a kinds filter, a note and an inspect produce the mounted desk. Run it with `python3 scripts/mod_host_check.py --omd-mod <omd-mod> --no-commands --scenarios approval_desk`; `scripts/client_acceptance.py` drives the client against real hosts.
