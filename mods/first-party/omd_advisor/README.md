# Independent turn advisor

`omd_advisor` is an opt-in API .9 mod. It owns cadence, evidence selection, the reviewer prompt, typed result/citation validation, semantic fingerprints and presentation. The host owns isolated worker execution, permissions, allowance, exact candidate/evidence/result bindings and the reviewer ledger. There is no advisor prompt or package-specific execution path in Rust.

Full installs this candidate inactive. Platform-only users may explicitly install and trust this package. Enabling it alone leaves `every_turn: false`; select `every_turn: true` and an authorized `route` to request a review after each completed lead turn. The controlled task must separately allow `review.every_turn_advice` and unified review. No account, model access or allowance is created by a mod setting. Read-only reviewers receive a selected evidence excerpt, no tools and no parent conversation; the selected current turn can include its visible user request. Hidden reasoning and tool-output bodies are excluded.

If the `omd-review-policy` plugin is also enabled, select `OMD_REVIEW_CADENCE_OWNER=advisor` in its hook environment. That disables the older manual-review Stop reminder so the mod can review the completed turn without a duplicate pre-stop review. It does not bypass the native ledger or final-review gate. The default unset value retains manual cadence.

`mode: advisory` is the default. Blocking candidates become warnings in that mode. `mode: blocking` also requires the native `review.extension_blocking` setting selected by the user; absent that authority, submission is denied. Advice never substitutes for final approval. The native ledger binds every accepted finding to its reviewer/model/provider, source evidence, exact workspace candidate and accounted worker result. Findings deduplicate on a reviewer-supplied concern key plus paths, and open keys for an unchanged candidate are offered back to the reviewer. Advice and warnings live in the ledger's bounded advisory lane: they never consume the enforced review cycle or open-finding budgets and expire when the candidate changes. Only a user-selected blocking finding enters the enforced ledger.

`turn_end` only requests the review; `agent_end` validates and submits the result, so the lead's turn never waits for the reviewer. Starting the next turn does not cancel a running review; it is replaced when that turn ends, and a result for a changed workspace is denied as stale. Exiting the session, including the end of a `codex exec` run, can interrupt a review that is still running. After a completed review, the mod wraps the fullscreen above-composer area with up to three typed notes. Inline terminal mode shows the short review status/count; its status tool returns the full bounded receipt after rechecking the current thread's evidence access. Notes are untrusted suggestions. The next context receives them only for the same thread and unchanged candidate. A new turn/start/resume hides the prior inline display. Resume never automatically relaunches an uncertain review. Denial, missing evidence, malformed results, invalid quotes and cancellation remain explicit; they do not count as a successful review.

Limits: at most 48 KiB read from the host evidence resource, a 6 KiB reviewer excerpt that keeps the newest records (clipping the newest one if it alone exceeds the excerpt), eight findings and eight file references per finding. If the evidence cannot be read within the limit, the turn is left unreviewed with an explicit reason. Compaction keeps the host's original visible evidence segments. No completed-turn subscription exists when `every_turn` is off; disabling the mod removes all callbacks and capture. Review remains subject to cancellation, task closure and the shared allowance.

Local synthetic native and runner tests exercise isolated review, disagreement, typed citations, duplicate/stale suppression, advisory versus selected blocking, denial, abort, cancellation, resume and disabled resources. The maintainer accepted this local implementation on 2026-09-27 with real-model qualification outside Batch 2 scope. Model access, review quality and actual cost remain unverified. This acceptance does not enable the mod or grant model use. The separate `omd_research` package never runs automatically alongside the advisor.
