# Guideline governance candidate

This API 0.2 package stores up to eight immutable development proposals and sixteen validation records in a repository-scoped, revision-checked state. Both native guideline variants are supported. A validation must reference the exact proposal digest and use task IDs disjoint from development evidence. Evidence references are checked through `evidence.read` while their record is made, and `evidence.write` records the proposal or validation. Proposals never activate themselves. The `promote` and `rollback` commands require an exact active selection, state revision, declared actor/reason, and canonical JSON slash arguments. Promotion requires a passed validation digest; rollback restores the previous explicit selection. Proposal and validation creation reject a changed workspace snapshot. Promotion and rollback reject changed store state but cannot recheck the current workspace snapshot through the TUI command host.

This remains a development candidate. The public command API does not authenticate a maintainer, and declared validator names/task IDs do not prove independent validation. Evidence references are scoped to their originating resource binding, so the stored record cannot prove continued access to an earlier thread's artifact. Store integrity and compare-and-swap protect this mod's state, but this is not a substitute for the native filesystem record and provenance policy. The record and history bounds are narrower than native. No guideline variant is selected by default. Do not delete native guideline support or claim promotion governance parity on this evidence.
