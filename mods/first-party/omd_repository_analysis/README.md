# Repository analysis candidate

`omd_repository_analysis` uses API 0.2 workspace reads and repository-scoped store. `graph` declares at most 4,096 files and 32 MiB of combined source from a requested subtree; the host's per-callback call, receipt, time and output limits can stop a request sooner. It recognizes Rust, Python, TypeScript, JavaScript, and Java. Lexical definitions and imports produce source-bound nodes and edges; resolved imports are extracted, calls are inferred, and unresolved or unsupported syntax stays unknown. The graph includes per-file SHA-256, a source-set digest, a candidate snapshot digest, and per-file coverage. `select` returns at most 32 KiB of evidence for 16 nodes. `html` returns a deterministic, self-contained interactive page with escaped source links, search, node and confidence filters, a neighborhood diagram and copyable evidence, bounded to 64 KiB. Both require the current source-set digest.

`graph_artifact` runs a hash-bound copy of this package's source in a sandboxed read-only Node process and stores the complete graph in a paged, thread-bound `exec.run` artifact. `html_artifact` uses the same path to create a standalone interactive HTML artifact from an expected source digest; `select_large` returns bounded source evidence. All three check the current workspace candidate before and after execution. The artifact API is available to other mods.

Artifact helpers use a distinct source traversal: they skip hidden directories and a fixed set of generated/dependency directories, but do not apply ignore files. Native workspace listing includes non-ignored hidden directories and applies ignore rules. Consequently, ordinary graphs and artifact graphs can have different source sets and digests even without edits. Use the digest from `graph_artifact` for `html_artifact` and `select_large`; digests across these traversal paths are not interchangeable.

`baseline` stores an immutable, approved rule set and its observations. `check` compares the exact constraints and current source digests, separates introduced findings from existing debt and uncertain imports, and labels repair scope as metadata only. Dependency boundaries are deterministic for resolved imports. Normalized function duplication and test-count/assertion/skip checks are inferred findings. Baseline test signatures also detect removed tests, reduced assertions, and newly skipped tests. Approval fields do not authorize edits. Unknown rule fields and stale or altered baselines fail closed.

The `omd.repository_analysis` 1.0.0 service exposes `search` and `select` for terminal consumers. Search accepts `query`, `page`, and `root`, and returns at most 32 rows with stable node IDs, labels, details, count, page, source digest, and provenance. Select requires `node_id` and `expected_source_digest` and returns at most 32 KiB of related nodes, relationships, coverage, and source guidance. Both methods default the identity to `workspace` and revision to `live-source`. They use two workspace listings around batched source reads, then verify each file with `workspace.stat` and SHA-256. Their provenance is `{ "workspace_snapshot": false, "validation": "double_list_and_hash" }`: it proves bounded reread consistency, not candidate snapshot attestation. A changed source set, content hash, or expected digest fails closed. Service results are suitable for live navigation but should not be treated as a validated candidate snapshot.

Graph tool calls list once, read in batches of 16 files and check the workspace fingerprint three times; live service calls list twice and hash-check in batches of at most 128 paths. There is no graph cache. The in-callback `graph` tool reaches the host's 32-call and 128 KiB receipt limits before 4,096 files/32 MiB; `graph_artifact` handles that ceiling. On a physical 4,096-file, 32 MiB fixture the mod's process took about 5.1 s against 3.1 s for the retired native builder, excluding host sandbox and artifact overhead.

The mod replaces the retired `omd-graph` and `omd-health` binaries and passes their retained acceptance behaviors: extracted/inferred/unknown labels, deterministic source digests, stale-input refusal, escaped HTML, tamper-evident baselines, and separated introduced findings versus existing debt. On the retained eight-file fixture it resolves two `./helper` imports that native left unknown. Artifact formats, unknown-node identifiers and anchor hashes differ from native, and `check` returns a report instead of a process exit code. It does not parse full language syntax or resolve package imports; lexical calls, duplicate bodies and verification markers require source review. Browser interaction with the HTML artifact has not been exercised.
