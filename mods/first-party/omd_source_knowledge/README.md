# Source knowledge candidate

This API 0.2 mod retains up to 16 source-backed facts and 8 bounded task evidence records in a repository-scoped store. Each fact records a file/line excerpt and file/excerpt SHA-256. Evidence capture copies one current-thread resource page of at most 8 KiB into the store with a payload hash and workspace candidate hash. A later thread can reuse the stored copy without reopening the original thread-scoped resource. The caller supplies the repository and task identities; they are not host-attested.

Up to 8 inferred lessons can cite retained evidence. Proposals stay inert. An explicit `approve_lesson` command selects a candidate at an exact store revision; `remove` invalidates dependents, and `reset` advances the generation. Each command accepts one canonical JSON argument and returns a TUI-compatible display value. All command paths use only `store.get` and `store.put`, the operations available in the current TUI command host. Approval stores a caller-supplied actor and reason; removal and reset validate them but do not retain an event log. The mod cannot authenticate that actor or prove a user action beyond the TUI command origin.

Source facts accept repository-relative paths, including harmless hidden files, but reject traversal and `.git` components. The host's workspace path checks reject symlink components and enforce read permission. Excerpts use native's 200-line and 32 KiB bounds, require nonblank trimmed text, and exclude secret patterns. The mod rechecks file hashes and read access after reading. Reuse refreshes facts with a store revision check and omits missing or excluded facts. It returns only approved lessons whose evidence IDs remain retained. Cold sessions return no reusable facts or lessons. Inspect exposes records and status. The internal store schema 2 reads and migrates preview.1 facts-only state on the next write; the serialized state is capped below the host's store value limit.

A cold session uses one store read. Reuse uses one store read, two snapshot checks, two batched stats, one batched read and one access check across the 16 facts; changed facts add one compare-and-swap store write. Evidence capture uses one store read, two snapshots, one evidence read and one CAS write. Lesson proposal and each command use one store read and one CAS write. These are operation bounds, not measured latency or a native-versus-mod cost comparison.

This is a development candidate, not native knowledge parity. Evidence capture is limited to a single 8 KiB resource page rather than native 1 MiB artifacts and requires the original thread-scoped resource to be readable at capture time. The public evidence read does not attest the native `turn` resource kind or derive the native workspace hash and thread task ID. There is no native event log or frozen context revalidation; host-bound repository/task identity, maintainer authorization, user-action confirmation, full source provenance policy, and live TUI/PTy proof remain open. Guideline proposal/validation/promotion/rollback and Pi user-agent resource discovery remain separate work. Do not remove their native implementations on this evidence.
